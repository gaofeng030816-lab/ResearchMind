日期：2026-08-29（2026-08-31 同步 T6-D 冻结结果）
状态：Completed（T6-A/T6-B/T6-C/T6-D Completed）
当前验证基线：2.0.0rc1 本地内部候选（269 passed，1 项环境跳过；T5-BX 未批准）

## 1. 用户确认的产品要求

用户已明确确认进入 T6，并指定：

1. 代码界面必须成为独立工作区，不依赖先打开 PDF；
2. 同一代码工作区要适合零基础编程学习者；
3. 同一代码工作区也要服务需要理解并复现科研代码的工作者。

这是一项产品导航和代码工作流的架构定型；T6-A 决策本身不授权代码执行、
Shell、测试运行、依赖安装、代码写入、T5-B 工具或后台自主任务。其后用户另行
确认的 T5-B1 仅增加一个已选 Python 行范围的受控替换，不改变其余限制。

## 2. T6-A 推荐并获批的最小架构

| 决定 | 选择 | 理由 |
|---|---|---|
| UI 框架 | 继续 Streamlit | 独立工作区可由顶层导航解决，尚无证据支持 React/FastAPI 重写成本 |
| 进程形态 | 保持一个本地 Python 进程 | 满足个人研究工作台和现有测试/部署边界 |
| 持久化 | 继续会话内存 + Obsidian Markdown | 本需求不要求跨会话项目库；SQLite 触发条件尚未出现 |
| 顶层导航 | 论文阅读 / 代码学习与复现 / 只读助手 | 代码入口不再埋在 PDF 长页面之后 |
| 代码目标 | 零基础学习 / 科研复现 | 共享同一只读 CodeProject/CodeSelection，改变引导和解释问题，不复制后端 |
| 复现能力 | 先做静态项目概览和检查清单 | 不把“帮助复现”误解为自动运行未知代码 |
| T6-A 原始权限 | 维持 T3/T5-A 只读边界 | 无 shell、import、exec、测试、安装、写文件或任意路径工具；后续 T5-B1 是独立的窄写入合同 |

T6-A 不增加第三方依赖。候选入口、导入模块、语法/可读性状态等概览只从已经
索引的 `CodeProject` / 标准库 AST 结果确定性计算。

## 3. Problem / Before / After

**Problem**：当前六个面板纵向排列。代码功能虽然逻辑上可单独打开文件夹，但
用户必须先经过多个 PDF 面板，产品心智仍像“PDF 附属功能”；同一个通用解释
问题也无法区分新手学习和科研复现目标。

**Before**：

- 首屏按 PDF → 操作 → 对话 → 笔记 → 代码 → 助手顺序堆叠；
- 代码页没有独立入口；
- 只有文件数/体量信息，没有项目级静态概览；
- 所有人使用同一个默认解释问题。

**After（T6-A）**：

- 首屏以顶层工作区导航进入论文、代码或助手；
- 选择代码工作区时，即使没有 PDF，也可打开项目、查看概览、选择代码并解释；
- 新手模式提供术语友好的步骤引导与示例导向问题；
- 复现模式展示静态入口候选、导入模块、解析状态和人工复现检查清单；
- 两种模式都明确不执行代码，论文链接仅在用户已有 PDF 选择时作为可选能力。

可观察标准：

- AppTest 在未打开 PDF 的新会话中切换到代码工作区后，能打开临时项目；
- 项目概览能确定性报告文件/符号/导入/入口候选与问题文件；
- 切换学习目标会改变引导和默认问题，但不改变权限；
- 既有 PDF、EvidenceLink、T5-A 和 Vault 闭环继续通过。

## 4. 模块与数据流

- `models/code_context.py`：增加只读 `CodeProjectSummary`；
- `core/code_context.py`：从现有 `CodeProject` 纯计算项目概览；
- `app/use_cases.py`：公开概览用例；
- `app/app.py`：顶层工作区导航与条件组合；
- `app/views/code_workspace.py`：学习目标、概览、入门/复现引导；
- `app/state.py`：仅在确有持久导航需求时集中状态；普通 widget 状态仍由
  Streamlit 管理，不引入数据库。

数据流：

```text
用户选择代码工作区
→ 打开一个明确本地文件夹
→ code/ 只读索引 UTF-8 Python + 标准库 AST
→ CodeProject
→ core 纯函数生成 CodeProjectSummary
→ UI 展示学习/复现概览
→ 用户明确选择符号或行
→ 有界 CodeContext 预览
→ 用户点击后才调用 LLM
```

PDF、ResearchContext 和 EvidenceLink 不参与代码工作区的必需路径；若用户先在
论文工作区建立了选择，可在代码页额外创建用户确认链接。

## 5. 风险、回滚与验证

风险：

- 条件渲染可能让旧 AppTest 找不到部件；
- Streamlit widget key 若跨模式复用，可能显示错误的默认问题；
- “复现”字样可能被误解为已经运行或验证代码；
- 入口候选和依赖模块只是静态线索，不能冒充可运行性结论。

控制：

- 先写导航/无 PDF 代码路径的失败测试；
- 模式使用独立 question key；
- UI 明确标注“静态概览”和“尚未运行”；
- 保留所有原有 use case、模型和安全限制，不移动基础设施职责。

回滚：恢复 `app/app.py` 顺序组合并移除概览模型/纯函数即可；PDF、代码读取、
LLM provider、Vault 和 T5-A 协议无需回滚。

T6-A Definition of Done：

1. 三个顶层工作区可独立进入；
2. 无 PDF 时代码学习/复现主路径完整可用；
3. 两种目标有不同、清晰且不夸大的引导；
4. 项目概览是纯函数且有边界/排序测试；
5. 在 T6-A 范围内，代码仍不被 import、执行、测试、安装或修改；
6. Streamlit 聚焦和全量回归通过；
7. 架构、产品规格、路线图、AGENTS 和 Skills 同步到 T6 Active。
