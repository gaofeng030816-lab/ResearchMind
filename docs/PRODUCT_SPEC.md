## 1. 产品概述

### 1.1 定位

ResearchMind 是一个 **AI-powered research reading and knowledge capture workspace**——"以 AI 理解和知识沉淀为核心的科研阅读工作台"。

它围绕科研阅读的真实闭环设计：读论文 → 遇到不懂的词要翻译 → 遇到不懂的概念/公式/算法要问 AI → 问懂了要回到论文上下文重新理解 → 最后要把理解沉淀为长期知识。

三条定位边界：

- ResearchMind **不是**小绿鲸等第三方 PDF 阅读器的替代品，不全面复制其功能；
- ResearchMind **不是** Zotero 的替代品，不重新实现文献管理；
- ResearchMind **不是** Obsidian 的替代品，不建立独立的长期知识管理系统。

ResearchMind 连接的是 Zotero 与 Obsidian 所代表的科研工作流：帮助用户完成从文献阅读、内容理解、问题提问，到知识整理和长期知识保存的完整过程。核心价值不是"提供一个 PDF 阅读器"，而是"帮助科研人员理解论文，并将理解转化为可以长期保存的知识"。

### 1.2 长期愿景

```
Paper ↔ Mathematics ↔ Code ↔ Notes
```

让"论文 — 数学 — 代码 — 笔记"四者在一个工作空间内互相引用、互相解释。
T3 已实现独立、只读 Python CodeContext；T4 已实现用户确认的显式
论文/数学/算法—代码证据链接，并可随 KnowledgeNote 导出。T5-B1 已实现当前
Python 选择的单范围 proposal/diff/确认/恢复/回滚，但仍不执行代码。
T6-D 冻结前又加入独立 Code → Obsidian 代码笔记：从当前选择生成带相对路径、
行号和符号 provenance 的专用 Markdown，先预览再显式保存，不依赖 PDF。
V3-G6 在同一 CodeContext 形状中加入 C、Java、Julia 和 R 静态读取；语言与提取
方式进入选择、提示预览和笔记 provenance。它不执行、编译或解析项目依赖。


发布策略：V1、当前 V2 和中间版本全部作为内部开发基线。最终公开发布需要在稳定的
论文阅读闭环之上具备代码识别、论文—数学—代码—笔记关联和更进一步的智能化；
这些能力必须先形成独立规格与架构决策，不回填到冻结的 V2 范围。

### 1.3 当前核心问题

把最核心的**科研阅读闭环**收拢到一处：

**打开本地 PDF → 阅读 → 选择文本 → 翻译 / 受限 LaTeX / AI 解释（概念/数学/算法/上下文）→ 多轮追问 → 知识整理 → 生成结构化 Markdown → 保存到 Obsidian Vault**

V3-G1 在不改变上述阅读闭环的前提下增加入口：

**点击/拖放导入 PDF 或支持语言代码目录 → 跨重启资料库 → 打开当前托管修订
进入既有论文/代码旅程**

G1 支持精确哈希去重、显式修订、软移除/恢复、单独确认删除托管副本和资料库
备份/恢复。它不持久化对话、选择、证据链接或笔记草稿。

V3-G2 又增加一个默认关闭的可选入口：

**点击上传 PDF → 点击读取 Zotero 个人资料库 → 选择条目/附件 → 链接已有论文**

它不写 Zotero、不后台同步、不缓存整库，也不替代 Zotero 的集合/引用管理。
另一路径是：配置批准的附件目录 → 选择一个 PDF → 单独确认 → Windows 只读
复制 → G1 校验/托管 → 来源链接。使用 /file/view/url，HTTP 重定向仍拒绝；不支持
网络路径、越界、重解析点或硬链接。原件不变；非 Windows/未配置时手动上传后链接。
当前 adapter 要求 Zotero 10+ 的 server identity，缺失时失败；用户已于
2026-09-04 确认真实桌面人工验收通过。

## 2. 目标用户与核心场景

### 2.1 目标用户

- 需要阅读外文论文的学生与研究者（论文以英文为主，界面语言中文）。
- 已使用 Zotero 管理文献、使用 Obsidian 管理长期知识的科研工作者：ResearchMind 不替代这两者，而是连接它们。
- 项目开发者本人：Python 初/中级水平，工具必须能被自己读懂和维护——这是产品约束，也是架构约束。

### 2.2 核心场景（当前 V2）

| # | 场景 | 痛点 |
|---|------|------|
| S1 | 阅读论文时遇到不懂的句子/术语 | 要在翻译软件与论文之间来回切换 |
| S2 | 翻译后仍不理解概念/公式/算法 | 要去搜索引擎/AI 单独提问，且提问不带论文上下文 |
| S3 | 理解了一个点之后还想继续追问 | 与通用 AI 聊天时论文上下文已丢失，需要重新粘贴背景 |
| S4 | 想保存这次问答的结果 | 手动复制到笔记软件，丢失出处（哪篇论文、哪一页），且与自己的 Obsidian 知识体系脱节 |
| S5 | 阅读科研代码时想理解函数/类型/方法 | 通用 AI 缺少语言/文件/行/符号来源，复制过多代码又增加隐私和上下文噪声 |
| S6 | 理解代码后想保存到 Obsidian | 手动复制容易丢失相对路径、行号、符号、问题和解释之间的对应关系 |

### 2.3 V3 已确认场景与状态

- **V3-G1 已实现**：跨重启管理 ResearchMind 本地论文/代码工作资料库并点击/
  拖放导入 PDF 或 Python/C/Java/Julia/R 代码目录；
- **V3-G2 已验收**：可选从 Local API 获取个人资料库条目，链接文献元数据/
  附件来源及批准目录内 Windows 单 PDF 复制；真实 Zotero 人工验收已由用户确认通过；
- **V3-G3 已实现**：在 PDF 文字层直接划词并保留页码/几何位置，论文全宽、
  论文+代码分栏，并提供输入安全的 AI 快捷键；
- **V3-G4 已验收**：点击翻译、显式证据篮、持久可编辑 Markdown 草稿与可选
  Obsidian 保存；
- **V3-G5 已实现**：识别当前页常用公式候选区域，生成可编辑、可校验、可追溯
  的 LaTeX 候选；
- **V3-G6 已实现**：在现有 CodeContext 架构中静态读取 Python、C、Java、Julia
V2→V3 过渡要求。

## 3. V2 用户旅程

```
1. 打开本地 PDF
   ↓
2. 阅读论文（翻页/缩放/搜索，看到页面图像与该页提取文本）
   ↓
3. 一键选择文本/公式块，或复制/手动输入一段文本
   ↓
4. 点击"翻译" / "AI 解释"（概念/数学/算法/上下文模式）
   ↓
5. 查看回答；不满意则继续追问（对话式）
   ↓
6. 把有价值的问答整理成知识笔记（含自己的理解与标签）
   ↓
7. 预览生成的结构化 Markdown
   ↓
8. 保存到自己的 Obsidian Vault
```

T3 代码旅程独立存在：

```text
打开一个本地文件夹 → 选择 Python 文件 → 选择 AST 符号或行范围
→ 检查 CodeContext 发送前预览 → 显式请求 AI 解释
→ 可选预览代码笔记 → 显式保存到 Obsidian
```

T4 在两条解释旅程旁增加显式链接：

```text
已定位论文/数学/算法选择 + 当前代码选择
→ 用户填写关系与置信度并确认
→ 会话内 EvidenceLink → KnowledgeNote / Obsidian Markdown
```

链接不触发模型调用，不自动发现对应关系，也不合并两个上下文 prompt。

T5-A 提供一条独立、逐次确认的只读助手旅程：

```text
输入综合问题 → 点击开始 → 模型请求一个固定只读来源
→ 本地展示待发送结果 → 用户点击继续或停止
→ 最多 3 个工具/4 次 LLM → 当前会话最终回答
```

它不写入论文 Conversation、KnowledgeNote、Vault 或代码。

T5-B1 在普通代码解释旁提供一条独立受控修改旅程：

```text
当前 CodeSelection → 输入修改要求 → 点击生成 proposal（不写盘）
→ 检查相对路径 unified diff / 语法 / 体量
→ 单独确认 → 恢复副本 + 原子写入
→ 需要时再次确认并按 SHA-256 安全回滚
```

它只修改一个当前已选既有 `.py` 行范围；无 Shell、测试、安装、Git 或多文件权限。

## 4. V2 功能需求

每条需求包含：描述、输入/输出、验收标准（Given/When/Then）。

### FR1 打开本地 PDF

- **描述**：用户从本地文件系统选择一个 PDF 文件打开。当前 V2 不维护论文库：每次会话直接打开，不记录、不去重。
- **输入**：本地 PDF 文件路径（文件选择器或路径输入）。
- **输出**：阅读界面显示该论文（标题、页数等元数据与第一页）。
- **验收**：
  - Given 一个合法 PDF → When 打开 → Then 阅读界面显示该论文且可浏览；
  - Given 路径不存在或非 PDF/损坏文件 → When 打开 → Then 显示明确错误，应用不崩溃；
  - Given 已打开一篇论文 → When 打开另一 PDF → Then 当前论文被替换为新论文。

### FR2 阅读 PDF

- **描述**：打开论文后能浏览每一页；能翻页、按页码跳转、缩放页面、在文档内搜索文本；能看到页面图像、按阅读顺序排列的文本块，以及可检测到的嵌入图表/图片区域。
- **验收**：
  - Given 已打开的论文 → When 点击翻页 → Then 显示对应页的图像与文本；
  - Given 多页论文 → Then 页面按原顺序编号，不重不漏；
  - Given 输入缩放倍率 → When 缩放 → Then 页面图像按倍率重新渲染；
  - Given 一个双栏数字版 PDF → When 提取文本 → Then 文本块优先按栏阅读顺序排列，视觉换行被整理为可复制段落；
  - Given 当前页包含嵌入位图 → When 打开页面 → Then 可预览并下载对应图表/图片区域；
  - Given 一个搜索词 → When 搜索 → Then 返回命中页与文本块摘录，且可跳转到命中页。

### FR3 选择 / 指定一段文本

- **描述**：用户可从当前页一键选择普通文本块或公式候选，也可复制/直接输入文本。系统保留 page、block 和可用 bbox；手动文本先当前页查找，找不到再查全论文。
- **验收**：
  - Given 一个普通文本块或公式候选 → When 点击对应选择按钮 → Then 一次点击形成当前 `ReadingSelection` 并同步选中文本框；
  - Given 当前页文本包含该段落 → When 提交选中文本 → Then 定位到当前页对应文本块；
  - Given 当前页不含该文本但论文其他页包含 → When 提交 → Then 定位到对应页；
  - Given 定位成功且源块有 bbox → Then 发送前预览和知识笔记显示 page/block/bbox；
  - Given 论文中不存在该文本 → When 提交 → Then 提示未定位，仍允许使用该文本进行翻译/解释。

### FR4 划词翻译

- **描述**：把选中文本翻译成目标语言（默认中文，可在配置中修改）。翻译是独立的 Translation 模块能力，与"AI 解释"（FR5–FR8）在产品与架构上相互独立。
- **验收**：
  - Given 一段英文选中文本 → When 点击"翻译" → Then 返回中文翻译，并显示在对话面板中；
  - Given 翻译服务调用失败 → When 点击翻译 → Then 显示错误信息，应用不崩溃。

### FR5 AI 概念解释

- **描述**：对选中文本中的专业概念给出解释（面向科研读者，简洁、准确），并尽可能结合论文上下文（见 FR8）。
- **验收**：同 FR4 的流程，返回概念解释。

### FR6 AI 数学解释

- **描述**：解释选中内容中的数学符号、公式与数学关系（例如 "What does y^k mean in this equation?"），并结合论文上下文（见 FR8）。
- **验收**：
  - Given 数字版 PDF 文字层包含高置信度公式/符号块 → When 打开该页 → Then 阅读器标记公式候选、保留可用换行并允许逐块复制；
  - Given 含公式/符号的选中文本 → When 点击"数学解释" → Then 返回对符号/公式含义的解释。
  - Given 选择附近存在公式候选 → When 展开上下文预览 → Then 可以看到将发送的邻近公式文字层；复杂二维排版仍提示对照页面图像。
  - Given 用户确认了一段数学文字层选择 → When 点击“转换为 LaTeX” → Then
    使用同一有界 ResearchContext 返回一个可复制的受限表达式，并在本地显示
    数学预览；
  - Given 模型返回整篇 TeX、显示分隔符、宏/文件/链接命令或无法解析的格式 →
    Then 拒绝展示和保存，应用显示项目错误且不执行任何 TeX。

### FR7 AI 算法解释

- **描述**：解释论文中的算法与算法步骤（例如 "Why does QMME update x^{k+1} this way?"），并结合论文上下文（见 FR8）。
- **验收**：
  - Given 算法相关的选中文本 → When 点击"算法解释" → Then 返回对算法步骤/动机的解释。

### FR8 基于论文上下文的解释

- **描述**：所有解释模式（FR5–FR7）自动附带选中文本在论文中的最小必要
  上下文，包括同页相邻文本块、论文标题等元数据，以及能够高置信度识别时的
  最近章节标题、邻近图表说明和邻近公式候选，使解释结合论文语境，而非孤立回答。
- **验收**：
  - Given 选中文本 → When 任一解释模式 → Then 回答体现出对论文语境的引用；
  - Given 选中块前存在章节标题或附近存在图表说明/公式候选 → When 构建上下文 → Then
    提示词包含受长度和距离限制的结构线索；
  - Given 文本无法定位或没有高置信度结构线索 → Then 对应字段为空，不附加
    任意全文内容；
  - Given 已确认选中文本 → When 展开解释上下文预览 → Then 在不调用网络的
    情况下看到来源类型、页码、文本块、bbox、章节、图表说明、邻近公式、当前问题、选中文本、周边文本、预算内历史
    数量和近似请求体量；
  - Given 点击 LaTeX 转换 → When 展开其上下文预览 → Then 预览与实际转换使用
    相同 ResearchContext 和 LaTeX prompt builder；
  - Given 输入有效追问 → When 展开追问上下文预览 → Then 预览与实际追问使用
    相同的 ResearchContext 和 prompt builder；
  - Given 上下文过长 → Then 按预算截断，不报错。

### FR9 后续追问

- **描述**：在同一篇论文的对话中继续提问，AI 能看到之前的问答与选中文本。
- **验收**：
  - Given 已有一次翻译/解释 → When 输入追问 → Then AI 回答与上文连贯；
  - Given 论文对话历史较长 → Then 按预算保留最近消息，不报错。

### FR10 知识沉淀到 Obsidian

- **描述**：把对话中要保存的内容（原文、翻译、经校验的 LaTeX、用户的问题、AI 解释、用户自己的理解）和当前显式证据链接整理成知识笔记，生成结构化 Markdown，并保存到用户指定的 Obsidian Vault。笔记必须包含来源信息（文档标题、作者、页码），以追溯回原始论文。
- **输入**：勾选的对话内容 + 用户自己的理解 + 标签 + 笔记标题 + 当前会话证据链接。
- **输出**：Vault 指定子目录下新增一个 `.md` 文件。
- **验收**：
  - Given 一次问答或 LaTeX 转换 → When 保存 → Then Vault 中出现 `.md` 文件，包含来源、原文、可选显示公式、翻译、问答、用户笔记、标签与可选证据链接；
  - Given 未配置 Vault 路径 → When 保存 → Then 显示明确错误，提示配置；
  - Given 同名笔记已存在 → When 保存 → Then 追加序号，不覆盖已有文件。

### FR11 只读 Python CodeContext（T3）

- **描述**：用户明确打开一个本地文件夹，应用在固定规模和排除规则内只读索引
  UTF-8 Python；用户选择一个 AST 符号或明确行范围，在发送前检查有界代码证据，
  再显式请求 AI 解释。
- **输入**：本地文件夹、Python 文件、符号或起止行、当前问题。
- **输出**：带 relative path / line / symbol provenance 的 CodeContext 预览和
  非执行型 AI 解释。
- **验收**：
  - Given 合法 Python → Then import、函数、类、方法具有相对路径和起止行；
  - Given 语法错误 → Then 仍可按行选择；Given 非 UTF-8 → Then 只显示诊断；
  - Given 超过 2,000 文件/20 MB/单文件 1 MB → Then 明确拒绝并要求缩小范围；
  - Given 源码包含命令或提示注入 → Then 应用只解析/转义文本，不执行代码；
  - Given 打开预览 → Then 不调用网络；Given 点击解释 → Then 只发送预览中的
    选中代码、最小邻近代码、相对路径/行/符号和问题，不发送绝对根路径或整个项目。

### FR12 用户确认的证据链接（T4）

- **描述**：用户把一个已定位的论文内容、数学公式或算法选择与当前代码符号/
  行范围显式关联。应用记录双方来源、定位、关系、用户置信度、生成方式和可选
  判断依据；链接不调用模型。
- **输入**：`ReadingSelection`、`CodeSelection`、论文证据类型、关系、
  0–1 置信度、可选判断依据。
- **输出**：会话内 `EvidenceLink`，以及 KnowledgeNote/Obsidian 中的可追溯
  证据链接段落。
- **验收**：
  - Given 论文选择有页码且代码选择仍匹配当前项目 → When 用户点击确认 →
    Then 链接包含 document/page/block/bbox 与 project/relative-path/line/symbol；
  - Given 论文没有可靠页码、代码项目不匹配、源码已变化或置信度越界 →
    Then 拒绝建立链接并显示明确错误；
  - Given 同一端点、关系和来源已存在 → Then 拒绝重复链接；
  - Given 链接已建立 → Then UI 和 Markdown 显示“用户确认”、关系和置信度；
    `deterministic` / `model_inference` 虽可由模型表达但不能冒充用户确认；
  - Given 生成 KnowledgeNote → Then 当前链接被复制并随 Markdown 导出；
  - Given 打开新 PDF 或新代码项目 → Then 清空会话链接，避免跨来源串联。

### FR13 逐次确认的只读研究助手（T5-A）

- **描述**：用户围绕当前论文选择、当前 Python 代码选择和当前显式证据链接
  提出综合问题；模型每一步只能请求一个固定、无参数的只读工具或返回 final。
- **输入**：明确问题和当前会话已有证据。
- **输出**：待发送工具结果、非敏感审计元数据，以及独立的当前会话最终回答。
- **验收**：
  - Given 用户尚未点击开始/继续 → Then 不进行下一次 LLM 调用；
  - Given 模型请求白名单工具 → Then 应用本地构建有界证据并先展示给用户；
  - Given 工具结果包含提示注入 → Then 作为转义后的不可信数据发送；
  - Given 未知/带参数/重复动作或调用/字符预算越界 → Then 可预测停止并审计；
  - Given provider/tool 失败或用户停止 → Then 原有对话、链接、笔记、Vault
    和代码保持不变；
  - Given 新来源或选择改变 → Then 旧助手会话失效；
  - Then 没有 shell、任意文件读取、写入、执行、网络搜索或后台循环。

### FR14 独立代码学习与静态复现工作区（T6-A）

- **描述**：用户无需先打开 PDF，即可独立打开一个本地 Python 项目，并按
  “零基础学习”或“科研代码复现”目标阅读代码。
- **输入**：用户明确选择的一个本地文件夹、目标模式、代码符号或行范围和问题。
- **输出**：不含绝对路径的静态项目概览、有界 CodeContext 预览和用户显式
  请求后的非执行解释。
- **验收**：
  - Given 当前没有打开 PDF → When 用户切换到代码工作区 → Then 可打开代码
    项目、选择代码和请求解释，论文控件不是前置条件；
  - Given 选择零基础学习 → Then UI 给出从项目概览到选择代码、检查发送内容、
    提问的分步引导，并使用面向初学者的默认问题；
  - Given 选择科研代码复现 → Then UI 展示候选入口、import、候选第三方依赖、
    解析问题文件和明确的“尚未运行代码”提示；
  - Given 项目含语法错误或不可读文件 → Then 概览如实计数并列出相对路径；
  - Then 概览只复用已索引 CodeProject，不额外读取 README、requirements、
    环境、配置或数据说明，也不 import、安装依赖或执行测试；该静态路径本身
    不写源码，写入仅通过 FR16；
  - Given 当前另有论文选择 → Then 论文—代码链接仍是可选的显式操作，不会
    阻塞或污染独立代码学习流程。

### FR15 本地配置诊断与可验证恢复（T6-B）

- **描述**：用户可以在首次启动/升级后显式检查本地配置，并对 ResearchMind
  导出的 Markdown 创建可校验备份、恢复到新目录。
- **输入**：本地配置；配置的 Vault/子目录；用户指定的新 ZIP 或恢复目标。
- **输出**：不含凭据/绝对 Vault 路径的检查报告，或带 manifest/SHA-256 的
  Markdown ZIP 与非覆盖恢复结果。
- **验收**：
  - Given 用户点击或运行 diagnose → Then 检查不联网、不显示 Key、不创建目录；
  - Given LLM/Vault 未配置 → Then 作为可选能力 warning，本地阅读仍可启动；
  - Given 配置格式、LLM URL 或 Vault 目标无效 → Then 返回明确 error；
  - Given 创建备份 → Then 只包含配置子目录中的普通 `.md` 和 manifest，
    不含 `.env`、PDF、代码、图片或其他 Vault 内容；
  - Given 归档有路径穿越、重复/加密/符号链接成员、非 Markdown、清单/大小/
    SHA-256 不一致或超限 → Then 在写入前拒绝；
  - Given 恢复目标已存在 → Then 拒绝且不改变其中任何文件；
  - Given 合法归档和不存在的新子目录 → Then 恢复后内容哈希一致。

### FR16 当前 Python 选择的受控替换（T5-B1）

- **描述**：用户可要求模型只为当前 `CodeSelection` 的一个既有 Python 行范围
  提出替换。proposal 先经严格协议、改变行/文件大小、UTF-8、整文件 AST 与 hash
  校验，并展示 unified diff；应用和回滚分别需要用户确认。
- **输入**：当前项目、当前代码选择、明确修改要求、每次动作的确认。
- **输出**：会话内 `CodeChangeProposal`、不覆盖恢复副本、更新后的单文件索引、
  apply/rollback receipt 和不含源码/绝对路径/Key 的会话审计元数据。
- **验收**：
  - Given 只生成建议或用户取消/未确认 → Then 磁盘零变化；
  - Given 输出带路径/命令/多 wrapper/说明、空/NUL、超过 20,000 字符，或候选
    超过 400 changed lines / 1 MiB / 无效 UTF-8/Python → Then 拒绝且不写入；
  - Given 合法 proposal 且用户确认 → Then 写前建立 `.researchmind-recovery/`
    不覆盖副本，再用同目录临时文件原子替换目标；
  - Given proposal 后磁盘已改变 → Then original SHA-256 冲突并拒绝应用；
  - Given 应用后文件被外部编辑 → Then applied SHA-256 冲突并拒绝回滚；
  - Given 安全回滚 → Then 恢复原始 bytes，恢复副本仍保留；
  - Then 不提供 Shell/PowerShell、import/exec、测试、安装、Git、任意路径、
    多文件、创建/删除/重命名源码或后台 Agent 权限。

### FR17 可选 Code → Obsidian 代码笔记（T6-D）

- **描述**：在不打开 PDF 的代码工作区中，用户可把当前 `CodeSelection`、当前
  问题、与该选择绑定的 AI 解释、自己的理解和标签整理成代码专用
  `KnowledgeNote`，预览 Markdown 后再显式写入配置的 Vault。
- **输入**：当前项目与仍匹配索引源码的代码选择；可选当前解释；标题、问题、
  用户理解和标签。
- **输出**：仅含项目名、相对路径、行号、符号/提取方式和代码内容的非覆盖
  `.md` 文件；不含绝对项目路径或虚构的 PDF 页码。
- **验收**：
  - Given 未打开 PDF 但已有当前代码选择 → When 生成预览 → Then 代码 Markdown
    含相对路径、行范围、符号、缩进代码块和可选问答；
  - Given AI 解释不属于当前选择、问题文本已在解释后改变，或选择不再匹配索引
    源码 → Then 拒绝捕获或不写入过期解释；
  - Given 只生成预览 → Then 不写 Vault；Given 用户明确保存 → Then 只通过
    `integration/obsidian/` 非覆盖创建 Markdown；
  - Given 重新选择、重新解释、应用或回滚 T5-B1 修改 → Then 旧代码笔记预览失效；
  - Then 该功能不写源码、不调用模型、不提供 Shell/测试/安装/Git 权限。

## 5. 非功能需求（V2）

| 类别 | 要求 |
|------|------|
| 简单性 | 单进程 Python 应用，一个命令启动；代码可被初/中级 Python 开发者读懂 |
| 本地优先 | V2 路径可继续从原位置只读打开；G1 上传使用独立 ResearchMind 托管副本/SQLite 元数据，托管代码只读；G2 默认关闭且仅在显式按钮后访问 loopback Zotero；T5-B1 只用于外部项目的当前选择；知识仍以显式 Markdown 写入 Vault |
| 性能 | 常规论文（<100 页）打开与翻页无明显卡顿（目标 <2s/页） |
| 数据安全 | API Key 不落代码/日志；论文与代码调用仅发送选择+有界上下文；发送前预览不联网；TeX 和代码都不执行 |
| 可测试性 | 核心逻辑为纯函数；LLM 全程可 mock；所有测试不调真实 LLM API |

## 6. 功能边界（V2 历史边界 + G1 当前增量）

> 规则：不在本版本列表里的功能一律不做；发现"顺手的"功能先记录、不实现。

| 不做的事 | 计划归属 |
|----------|----------|
| 完整引用/书目/集合管理（Zotero 已有） | 永不替代 Zotero；G2 只保存显式来源链接 |
| 长期知识管理/双向链接体系（Obsidian 已有） | 永不（不替代 Obsidian） |
| 在 PDF 页面图像上精细划词（文字层选择） | Post-V2 候选；等待 V3 要求，不阻塞 V2 验收 |
| PDF 标注、高亮、书签 | Post-V2 候选；等待 V3 要求 |
| 整页/整篇 PDF→LaTeX、扫描整页 OCR、语义表格和图表内容理解 | G5 只检测当前页 bounded 候选并识别用户确认的一张 crop；不得扩成批量、后台或原源码恢复 |
| 通用 TeX 文档编辑/编译、宏执行、LaTeX 文件或网络访问 | 不属于当前科研阅读闭环；确有文档生成需求时单独评审 |
| 页面定位（跳转到原文位置高亮） | Post-V2 候选；等待 V3 要求 |
| 高级章节树、跨页图表语义关联与学习式结构识别 | Post-V2 候选；当前仅有保守规则线索 |
| Zotero 写入/双向同步、Web API、组资料库产品流或全库缓存 | G2 仅实现默认关闭的个人资料库 Local API 只读流；其他能力需独立门禁 |
| 跨论文搜索、复杂 RAG | 候选（未排期，确需再评估） |
| 跨会话对话、证据篮和 NoteDraft 持久化 | G4 已实现显式草稿/证据、证据篮、可编辑正文、同版预览与明确 Vault 输出；对话仍不持久 |
| C++/Notebook、跨文件调用图、依赖解析或 IDE 深度集成 | G6 只支持 Python/C/Java/Julia/R 静态读取；其余另行评估 |
| 自动 Paper ↔ Code 发现、模型推断链接、联合论文/代码 prompt | T4 仅实现用户确认、会话内链接；自动化需后续独立评测 |
| 超出 T5-B1 当前选择单范围的代码生成/修改；运行 shell/测试、安装依赖或其他模型工具 | 未授权；执行需独立 T5-BX 沙箱 Spike 与权限门禁 |
| VS Code Extension、浏览器 Extension | 候选（未排期，确需再评估） |
| 多用户、云端部署、复杂身份认证、移动端、多端同步 | 远期，无计划 |
| 向量数据库、知识图谱 | 远期，无计划 |
| 微服务 / Kubernetes / Redis / Celery | 永不（除非有充分理由推翻本规则） |

## 7. 当前版本范围

当前源码版本为 `3.0.0rc1`，核心用户闭环是：

```text
导入论文或代码
→ 明确选择文本、公式区域或代码范围
→ 翻译/解释/公式候选
→ 用户选择证据并编辑 Markdown 草稿
→ 预览
→ 明确确认后非覆盖写入 Obsidian
```

当前不提供整篇 PDF→LaTeX、扫描整页 OCR、Zotero 写入/同步、代码执行、
多文件自动修改、云同步或后台自主 Agent。未来能力只有在独立设计、安全与测试边界
明确后才能进入当前产品合同。
