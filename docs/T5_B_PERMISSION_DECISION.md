## 1. 为什么 T5-B1 不等于任意 Agent

用户已明确确认本文件推荐的 T5-B1：当前选择所属的一个既有 Python 行范围、
预览、逐次确认、恢复副本、SHA-256 冲突保护和安全回滚。该确认没有授权运行
未知代码。当前单进程 Streamlit、Windows 本机和标准库 `subprocess` 都不是安全
沙箱；超时或清空环境变量不能阻止未知测试读取文件、访问网络或启动子进程。

因此已实现的 T5-B1 仍不包含 Shell、PowerShell、任意命令、依赖安装、Git、
删除文件或后台循环授权。

## 3. T5-B1 已确认权限合同

### 3.1 模型能提出什么

- 只针对当前 `CodeSelection` 所属、已索引、仍存在的一个 `.py` 文件；
- 只返回一个严格、定长的行范围替换文本，不提供路径或命令参数；
- 替换文本不超过 20,000 字符，改变行数不超过 400；
- 应用先验证整个候选文件可 UTF-8 编码且能通过 `ast.parse`；
- 模型输出只是 proposal，永远不能直接触发写入。

### 3.2 应用如何写入与回滚

1. 记录索引时源码 SHA-256；磁盘内容已变化则拒绝；
2. UI 显示相对路径、原行范围、before/after unified diff、字符数和语法结果；
3. 用户对每次写入单独点击确认，停止/切换项目会使 proposal 失效；
4. 写前在项目内新建、不覆盖的 `.researchmind-recovery/` 恢复副本，并在 UI
   明确显示位置；该隐藏目录继续被代码索引排除；
5. 同目录临时文件写完、flush 后用原子替换更新目标；不创建、重命名或删除源码；
6. 回滚只在当前文件仍匹配“已应用版本”SHA-256 时执行，防止覆盖外部编辑；
7. 应用/回滚分别写元数据审计，不记录完整源码或 API Key。

### 3.3 明确没有的权限

- 无 Shell、PowerShell、终端、`subprocess`、import、eval、exec 或测试执行；
- 无依赖安装、Git、网络搜索、任意路径、目录递归写入或多文件批改；
- 无 PDF/Vault 写入、EvidenceLink 自动创建、后台循环或跨会话 Agent；
- T5-A 三个只读工具保持不变，模型不能把只读工具结果变成隐式写入批准。

## 4. T5-B1 退出证据

- proposal 协议拒绝路径、命令、多动作、超长/多文件输出和注入文本；
- 未定位/过期选择、源码 hash 变化、语法错误、符号链接和越界路径均拒绝；
- 没有用户确认时磁盘零变化；应用前恢复副本存在且不覆盖；
- 应用、用户取消、写失败、外部编辑冲突和安全回滚均有测试；
- AppTest 显示 diff/风险/确认；T6-C 桌面/窄窗口清单随后由用户明确人工确认通过，
  但没有自动浏览器截图证据；
- 全量回归继续保护 PDF→KnowledgeNote→Obsidian 和 T5-A 只读助手。
